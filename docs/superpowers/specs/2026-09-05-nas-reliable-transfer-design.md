# 群晖 NAS 可靠文件迁移工具设计文档

> 文档日期：2026-09-05  
> 文档状态：已获用户批准（2026-09-05）  
> 适用阶段：第一阶段——需求与技术设计  
> 技术基线：方案 A，PySide6 ＋ `smbprotocol` 直连 SMB  
> 首要质量属性：传输稳定性与源文件安全

## 1．背景与已确认决策

本项目面向 macOS 用户，用于将本地大文件或大量文件可靠地迁移到群晖 NAS。它不承诺网络或进程“永不中断”，而是保证中断能够被检测，连接能够恢复，已经确认的数据能够尽量复用，最终结果能够校验，源文件不会在目标完整性确认前被删除。

已确认的产品决策如下：

| 决策项 | 结论 |
|---|---|
| NAS 地址 | 同时支持 IP 地址、主机名和 `smb://` 地址 |
| 目录结构 | 保留源目录层级；多个独立来源保留各自顶层名称 |
| 同名冲突 | 默认自动重命名，最终名称写入持久化状态 |
| 任务模型 | 支持任务队列，但同一时刻只执行一个任务 |
| 密码保存 | 用户可选择保存到 macOS Keychain |
| 完整性校验 | 默认完整回读哈希；移动任务强制完整校验 |
| 技术方案 | PySide6 ＋ `smbprotocol` 直连 SMB |

稳定性优先于峰值吞吐量。MVP 不启用多文件并发传输，不把 SMB 挂载卷作为主传输通道，也不会为了速度降低校验与安全删除标准。

## 2．项目目标与非目标

### 2.1 项目目标

1. 在 macOS 上提供可安装、可视化的桌面应用。
2. 直接通过 SMB2／SMB3 连接群晖 NAS，不依赖 Finder 预先挂载共享目录。
3. 支持连接信息输入、测试、保存和编辑，密码可安全保存到 macOS Keychain。
4. 支持选择一个或多个本地文件／目录，并浏览或填写 NAS 目标路径。
5. 以单执行器串行处理持久化任务队列，避免并发传输争抢带宽和复杂化恢复状态。
6. 对网络切换、SMB 会话失效、Mac 睡眠／唤醒、应用退出、应用崩溃和 NAS 重启进行检测与恢复。
7. 使用远端临时文件、分块写入、持久化检查点、断点核验和同目录提交，尽量避免大文件从头复制。
8. 默认执行完整回读 SHA-256 校验，明确展示复制与校验两个阶段。
9. 将“移动”严格实现为“复制、完整校验、提交成功、再次确认安全条件，然后删除源文件”。
10. 为用户展示任务进度、当前文件、速度、预计剩余时间、重试状态、错误原因和最终报告。

### 2.2 非目标

MVP 明确不包含：

- 用户注册、云端账号和跨设备账号同步。
- 云存储、对象存储、FTP、SFTP、WebDAV 或其他 NAS 协议。
- 多人协作、共享审批和企业级权限管理。
- 多任务并发、多文件并发和带宽智能调度。
- NAS 到本地、NAS 到 NAS 的双向同步。
- 文件版本管理、增量备份和镜像同步。
- Finder 扩展、右键菜单和系统级后台常驻代理。
- 对符号链接目标的递归跟随。
- 保证所有 POSIX ACL、所有者、资源分叉和扩展属性在 SMB 两端完全等价。
- 在公网直接暴露 SMB 端口的远程访问方案。

## 3．稳定性目标与可验证承诺

### 3.1 对外承诺

产品用语采用以下表述：

> 在经过能力检测的群晖 SMB 共享上，应用能够检测传输中断，自动或手动重新连接，通过持久化检查点核验并继续传输；完成后回读目标文件进行完整性校验；移动任务仅在目标确认完整后删除源文件。

不得使用“绝不中断”“百分之百不会失败”或“零数据丢失”等无法由客户端单方面保证的措辞。

### 3.2 稳定性验收指标

在通过能力检测的真实群晖测试环境中，MVP 必须达到：

- 单个 50 GB 文件传输过程中随机断网 10 次，恢复后最终 SHA-256 一致。
- 每次已落盘检查点之后的重复传输量原则上不超过 64 MiB 加一个 4 MiB I/O 块；若 NAS 重启后服务端回退了已确认长度，以远端实际可验证内容为准。
- 单个 50 GB 文件传输过程中强制结束应用 20 次，重新启动后均不得误删源文件或把半成品暴露为最终文件。
- NAS 重启、Mac 睡眠／唤醒和 Wi-Fi 切换后，任务进入明确的等待或重连状态，不得无提示卡死。
- 迁移 100,000 个小文件时，内存占用不随全部文件内容增长；文件清单采用流式扫描、批量入库。
- 校验失败、源文件变化、目标空间不足、权限不足和源文件删除失败均有明确终态和可操作提示。

这些指标是发布验收条件，不是对所有网络和所有 SMB 服务端的无条件承诺。

## 4．用户流程与界面草图说明

### 4.1 总体流程

1. 用户创建或选择 NAS 连接配置。
2. 用户输入密码，选择是否保存到 Keychain，然后执行连接测试。
3. 用户选择一个或多个本地文件／目录。
4. 用户浏览或填写 NAS 目标目录。
5. 用户选择“复制”或“移动”，确认默认自动重命名策略和完整校验模式。
6. 应用扫描来源并执行预检：来源可读性、路径合法性、目标权限、目标剩余空间及 SMB 续传能力。
7. 任务进入队列，由唯一执行器按顺序处理。
8. 复制中断时自动重连；无法立即恢复时进入“等待网络”，保留断点。
9. 写入完成后关闭写句柄，以新读句柄从 NAS 回读并执行 SHA-256 校验。
10. 校验成功后将临时文件提交为最终名称；移动任务再进入安全删除阶段。
11. 任务结束后展示成功、失败、跳过、自动重命名和源文件保留情况。

### 4.2 NAS 连接配置页

界面包含：

- 配置名称。
- NAS 地址：接受 IPv4、IPv6、主机名、`.local` 名称和 `smb://host` 形式。
- 端口：默认 `445`。
- 共享目录名称。
- 用户名和可选工作组／域。
- 密码输入框。
- “保存密码到 macOS Keychain”开关，默认开启。
- “要求 SMB 加密”开关，默认开启。
- 高级安全选项：仅在受信任局域网中允许签名但未加密的 SMB2／SMB3，会显示持续警告。
- “测试连接”按钮和分阶段结果：地址解析、TCP 连接、SMB 协商、身份认证、共享访问。

`smb://nas.local/share/folder` 可以自动拆分为地址、共享目录和初始目标路径；用户仍可编辑拆分后的字段。连接配置只保存非敏感字段和 Keychain 条目标识，不保存密码。

连接配置页的测试默认只读。创建任务后的目标预检会在用户选定的目标目录中创建、写入、刷新、重新打开、偏移追加、截断、重命名和删除一个带随机 UUID 的小型探测文件，以验证该目录是否满足可靠传输协议，并在界面中明确说明该行为。

### 4.3 本地源文件／目录选择页

界面包含：

- “添加文件”“添加目录”和拖放区域。
- 已选来源列表，显示类型、预计大小和路径。
- 移除单项与清空列表操作。
- “保留目录层级”固定开启；MVP 不提供关闭入口。
- 动作选择：“复制”或“移动”，默认“复制”。
- 完整校验：默认开启；选择“移动”后强制开启且不可关闭。
- 冲突策略：默认“自动重命名”；同时展示“跳过”和“覆盖”选项，但 MVP 中“覆盖”要求二次确认且移动任务不默认使用。

多个独立来源在目标目录下保留各自顶层名称。例如同时选择 `/Users/me/A` 和 `/Volumes/Disk/B`，目标分别落入 `<target>/A` 和 `<target>/B`。

### 4.4 NAS 目标路径选择页

界面包含：

- 当前连接配置和连接状态。
- NAS 目录树、面包屑导航、刷新和新建目录。
- 可直接填写的共享内相对路径。
- 预计需要空间、NAS 报告的可用空间和安全余量。
- 目标路径的读、写、刷新、偏移写、截断、重命名和删除探测结果。
- 最终任务摘要和“加入队列”按钮。

目标浏览通过 `smbprotocol` 完成，不要求 Finder 挂载。目标路径必须限制在已选择的共享目录内，规范化后不得通过 `..` 或异常分隔符逃逸共享根目录。

### 4.5 迁移任务进度页

界面采用单窗口队列布局：

```text
┌──────────────────────────────────────────────────────────┐
│ 当前任务：照片归档                    状态：正在复制       │
│ 当前文件：旅行/视频/IMG_001.mov                         │
│ 复制进度：██████████████░░░░░  72%                      │
│ 校验进度：██████░░░░░░░░░░░░░  31%                      │
│ 速度：86.4 MiB/s   预计剩余：18 分钟   重试：0/8          │
│ [暂停] [取消] [查看详情]                                 │
├──────────────────────────────────────────────────────────┤
│ 等待队列                                                  │
│ 1. 工作资料       42 GB       等待                        │
│ 2. 摄影素材      618 GB       等待                        │
└──────────────────────────────────────────────────────────┘
```

进度要求：

- 复制与校验分开显示，避免复制达到 100％后用户误以为任务已经结束。
- 总进度以实际工作量计算；开启完整校验时，复制字节和目标回读字节均计入总工作量。
- 速度使用短期滑动窗口，预计剩余时间在样本不足时显示“正在估算”。
- 当前重连倒计时、累计重试次数、最近错误和下一步动作始终可见。
- Mac 进入睡眠前主动暂停并刷新检查点；唤醒后重新建立会话并执行断点核验。
- 暂停保留任务与远端临时文件。取消时提供“保留断点”和“删除临时文件”两种明确选择，默认保留断点。

### 4.6 任务结果页

结果按以下类别汇总：

- 已复制并校验。
- 已复制、校验并删除源文件。
- 已复制但源文件删除失败。
- 自动重命名。
- 跳过。
- 校验失败。
- 传输失败。
- 因源文件变化而中止。

用户可以复制摘要或导出脱敏报告。应用不把“目标成功但源文件删除失败”显示为完全失败，而是显示“迁移完成，但源文件仍保留”的警告终态。

## 5．技术选型

### 5.1 Python 版本

选择 Python 3.12 系列。

理由：

- 满足 `smbprotocol` 和 `keyring` 的 Python 版本要求。
- 相比刚发布的新主版本，第三方依赖、打包工具和 macOS 通用二进制兼容性更成熟。
- Python 3.12 的性能、类型能力和标准库足以支撑 MVP。
- MVP 不使用自由线程构建，降低 UI、数据库和 SMB 库的并发不确定性。

具体补丁版本在实施时锁定为当时仍受支持且通过完整测试矩阵的最新 3.12 补丁版本。

### 5.2 桌面 UI 框架

选择 PySide6 的 Qt Widgets，不采用 Tkinter、Electron 或 PyObjC 作为 MVP 主框架。

理由：

- PySide6 是 Qt 官方 Python 绑定，适合任务队列、树形目录、表格、进度和错误详情等桌面交互。
- Qt 的信号槽和工作线程模型可以将阻塞 SMB I/O 与主 UI 线程隔离。
- Qt 官方提供 `pyside6-deploy`，能够生成 macOS `.app`。
- 相比 PyObjC，开发和测试成本更低；相比 Tkinter，复杂桌面界面的组件能力和可维护性更强。

UI 主线程不得执行 SMB、哈希、文件扫描或 SQLite 长事务。传输执行器运行在单独工作线程，通过不可变事件向 UI 汇报状态。

### 5.3 SMB 客户端实现

选择 `smbprotocol`，优先使用其高层 `smbclient` 接口；只有当刷新、精确偏移、文件标识或重命名语义无法由高层接口满足时，才在隔离的 SMB 适配层中使用低层接口。

选择依据：

- 支持 SMB2 和 SMB3、NTLM／Kerberos、消息签名与 SMB3 加密。
- 能够直接打开、读取和写入远端文件，并支持随机访问偏移。
- 不依赖 Finder 挂载生命周期，应用可以识别身份认证、会话断开和共享权限错误。
- Python 生态中成熟度和可维护性优于自行实现 SMB 协议。

MVP 使用用户名和密码认证；Kerberos 仅保留接口扩展点，不进入首版范围。SMB1 永久禁用。

### 5.4 Keychain 凭据存储

选择 Python `keyring`，运行时强制验证实际后端为 macOS Keychain。

- Keychain `service` 使用应用固定标识。
- Keychain `account` 使用连接配置 UUID，而不是把密码或完整地址拼入键名。
- SQLite 仅保存 Keychain 条目标识。
- 如果 Keychain 不可用或后端异常，“记住密码”功能不可用；密码仅在当前进程内存中保留。
- 禁止自动回退到明文文件、环境变量或 `keyrings.alt` 一类低安全后端。

Python 字符串无法可靠保证内存清零，因此文档只承诺缩短密码驻留时间、避免复制、避免日志记录，不承诺进程内秘密的绝对零残留。

### 5.5 本地任务状态持久化

选择标准库 `sqlite3` 和单个 SQLite 数据库，位置为：

`~/Library/Application Support/NasMove/nasmove.db`

数据库文件权限限制为当前用户读写。关键状态更新使用显式事务，启用 WAL，并对检查点、校验成功和删除授权等关键事务采用 `synchronous=FULL`。进度 UI 的高频刷新不逐次写库，最多每秒合并一次；可恢复检查点按 64 MiB 或文件结束持久化。

应用使用单实例锁，防止两个进程同时消费同一队列。数据库不保存密码、SMB 会话密钥或认证报文。

### 5.6 完整性算法

选择 SHA-256。

- 标准库直接支持，不引入额外依赖。
- 对迁移完整性具备足够的碰撞安全性。
- 群晖场景通常受磁盘或网络吞吐限制，SHA-256 的额外 CPU 成本可以接受。
- 生成的摘要可被其他标准工具长期复核。

BLAKE3 虽然速度更高，但会增加第三方二进制依赖和跨架构打包风险，不进入 MVP。

## 6．系统架构与模块职责

```text
Presentation
├── ConnectionView
├── SourceSelectionView
├── TargetBrowserView
└── TaskQueueView
        │ commands / immutable events
Application
├── ConnectionService
├── TaskPlanningService
├── QueueCoordinator
├── RecoveryCoordinator
└── ReportService
        │
Domain
├── Task / TransferItem / Checkpoint
├── TransferStateMachine
├── RetryPolicy
├── ConflictPolicy
└── DeletionSafetyPolicy
        │ ports
Infrastructure
├── SmbGateway
├── LocalFileGateway
├── SqliteTaskRepository
├── MacOSKeychainCredentialStore
├── Hasher
└── RedactedLogger
```

### 6.1 Presentation

只负责输入、展示和用户命令，不包含复制、重试或删除判断。任何源文件删除按钮都只能发送领域命令，不能直接调用文件系统 API。

### 6.2 Application

- `ConnectionService`：地址解析、连接测试和能力探测。
- `TaskPlanningService`：扫描来源、建立目录映射、预分配目标名称、估算空间并生成任务项。
- `QueueCoordinator`：维护持久化队列，保证只有一个活动任务。
- `RecoveryCoordinator`：应用启动、会话重建和远端状态核验。
- `ReportService`：生成用户结果和脱敏诊断信息。

### 6.3 Domain

保存状态机和不可绕过的业务不变量，尤其是：

1. 未完成完整校验的文件不得获得源删除授权。
2. 快速校验结果不得用于移动任务的源删除。
3. 源文件在校验前后发生变化时不得删除。
4. 目标最终名称未成功提交时不得删除源文件。
5. 恢复后的旧删除授权不得跨 SMB 会话直接复用。

### 6.4 Infrastructure

将第三方库、操作系统和持久化细节限制在适配层中。`SmbGateway` 对上提供领域所需的最小能力：列目录、查询属性、打开读写、指定偏移、刷新、截断、同目录重命名、查询空间和删除临时文件。

## 7．任务与文件状态模型

### 7.1 任务状态

| 状态 | 含义 |
|---|---|
| `DRAFT` | 用户正在配置 |
| `PREFLIGHT` | 扫描来源和验证目标能力 |
| `QUEUED` | 已持久化并等待执行 |
| `RUNNING` | 正在复制文件 |
| `INTERRUPTED` | 上次运行非正常结束，等待三方状态核验 |
| `WAITING_FOR_NETWORK` | 自动重连次数耗尽，周期性等待恢复 |
| `PAUSED` | 用户暂停或系统睡眠前暂停 |
| `VERIFYING` | 正在回读目标进行完整校验 |
| `COMMITTING` | 临时文件正在提交为最终名称 |
| `DELETING_SOURCE` | 已获删除授权，正在删除源文件 |
| `COMPLETED` | 全部要求成功完成 |
| `COMPLETED_WITH_WARNINGS` | 目标成功，但存在源保留、跳过或元数据警告 |
| `FAILED` | 存在不可恢复错误 |
| `CANCELED` | 用户明确取消 |

### 7.2 文件项状态

核心文件项状态按以下顺序流转：

`PLANNED → TRANSFERRING → TRANSFERRED → VERIFYING → VERIFIED → COMMITTED → SOURCE_DELETE_AUTHORIZED → DONE`

异常分支包括：

- `INTERRUPTED`：会话或进程中断，可恢复。
- `WAITING_RETRY`：等待指数退避。
- `SOURCE_CHANGED`：来源指纹变化，不可继续当前断点。
- `VERIFY_FAILED`：完整哈希不一致，源文件保留。
- `SOURCE_RETAINED`：目标已成功，但删除源文件失败。
- `SKIPPED`：由冲突、类型或用户策略导致跳过。

每一次状态迁移都校验允许的前置状态。数据库不能通过直接修改状态跳过 `VERIFIED` 或 `COMMITTED`。

## 8．本地状态模型

SQLite 至少包含以下逻辑实体：

### 8.1 `connection_profiles`

- 配置 UUID。
- 显示名称。
- 规范化主机、端口、共享目录、用户名和域。
- 加密要求和最低 SMB 方言。
- Keychain 条目标识。
- 最近一次测试结果和时间。

### 8.2 `tasks`

- 任务 UUID、名称、动作类型和队列顺序。
- 连接配置快照，而不是只引用可变配置。
- 目标根路径、冲突策略和校验策略。
- 当前状态、创建时间、更新时间和恢复代次。
- 总文件数、总字节数、已复制字节数和已校验字节数。

连接配置修改只影响以后创建的任务；已入队任务保留原连接参数快照，但凭据仍通过连接 UUID 从 Keychain 获取。执行前允许用户显式将任务更新为新的连接配置。

### 8.3 `transfer_items`

- 文件项 UUID 和所属任务。
- 本地原始路径、规范化相对路径和最终远端路径。
- 远端临时文件名。
- 源类型、逻辑大小、设备号、inode、修改时间和创建时指纹。
- 文件状态、错误分类、重试次数和最终 SHA-256。
- 目标文件标识、最终大小、提交时间和删除授权代次。

### 8.4 `checkpoints`

- 文件项 UUID。
- 已刷新并确认的偏移量。
- 检查点末尾验证窗口的起点、长度和 SHA-256。
- 远端当时报告的文件长度。
- SMB 会话代次和持久化时间。

### 8.5 `attempts` 与 `events`

- 每次连接、恢复、复制、校验和删除尝试。
- 结构化错误分类、脱敏错误码和用户可见摘要。
- 事件用于审计和结果页，不保存密码、认证数据或完整敏感路径。

## 9．可靠传输协议

### 9.1 创建任务前的能力探测

可靠续传不是仅凭 SMB 版本推断。目标目录必须通过实际能力探测：

1. 创建随机 UUID 临时文件。
2. 写入两段已知内容并刷新。
3. 关闭后重新打开，读取并验证内容。
4. 在指定偏移追加数据。
5. 截断到已知长度并验证。
6. 在同一目录内重命名并验证旧名消失、新名出现。
7. 删除探测文件。

探测失败时：

- 身份认证或共享读取失败：拒绝创建任务。
- 目标不可写、不可刷新、不可截断或不可同目录重命名：拒绝执行移动任务。
- 可靠提交能力不足：MVP 同样拒绝普通复制任务，避免生成外观正常的半成品。
- 删除探测文件失败：提示用户手动清理并停止预检。

### 9.2 远端临时文件

每个文件使用同目标目录的唯一临时名称：

`.nasmove-<transfer_item_uuid>.part`

临时名称与最终名称映射保存在 SQLite 中。使用同目录临时文件可以避免跨目录移动的不确定性，并使最终重命名尽可能成为服务端原子操作。

目标目录中出现无法对应本地数据库任务的 `.nasmove-*.part` 时，应用只将其列为孤立临时文件，不自动删除。用户可以在清理界面核对创建时间、大小和路径后手动清理。

### 9.3 分块传输

- 基础 I/O 块大小为 4 MiB。
- 持久化检查点间隔为 64 MiB。
- 最后不足 4 MiB 的内容按实际长度写入。
- 单个 SMB `write` 返回的字节数可能小于请求长度，必须循环写满当前块，不能假设一次调用写完。
- 内存中最多保留有限数量缓冲区，默认总量不超过 32 MiB。
- 每个文件结束时无论是否达到 64 MiB，都必须刷新并记录最终检查点。

MVP 固定单文件、单流传输。分块大小未来可以基于协商能力和网络测量调整，但首版不进行多流并行。

### 9.4 已传输片段的确认逻辑

SMB 写响应只表示请求已经由服务端接受，不单独作为持久断点依据。检查点流程为：

1. 完成当前 64 MiB 区间的全部写入。
2. 对检查点末尾最多 4 MiB 的确认窗口计算 SHA-256。
3. 对远端写句柄执行 `flush`。
4. 查询远端当前长度。
5. 将确认偏移、远端长度和确认窗口摘要放入同一个 SQLite 事务并提交。
6. 只有事务提交成功后，UI 才显示该偏移为“可恢复进度”。

`flush` 是客户端能够获得的最强常规持久化信号之一，但不能代替最终完整回读校验，也不能对故障存储硬件作绝对保证。

### 9.5 中断恢复与断点核验

发生网络错误、SMB 会话失效、NAS 重启、应用崩溃或 Mac 唤醒后，旧文件句柄和旧删除授权全部失效。恢复流程为：

1. 关闭或丢弃旧会话，清理 `smbclient` 连接缓存。
2. 使用最新凭据重新建立 SMB 会话。
3. 重新验证共享和目标目录能力；短时恢复可以复用近期能力结果，但 NAS 重启后必须重新探测。
4. 查询临时文件是否存在及其实际长度。
5. 同时读取 SQLite 最新检查点和远端实际状态，不能单独信任任一方。
6. 从不超过两者的最新完整检查点开始，回读远端确认窗口，与本地相同区间重新计算的 SHA-256 比较。
7. 若不一致，按检查点向前回退，直到找到一致的安全边界；无法找到时将旧临时文件隔离并从零创建新的临时文件。
8. 若远端长度大于安全边界，先截断到安全边界，再从该偏移继续写入。
9. 若源文件指纹变化，停止续传并标记 `SOURCE_CHANGED`，不删除源文件。

远端存在最终文件而临时文件消失时，可能表示应用在重命名成功后、记录状态前崩溃。恢复逻辑必须读取最终文件属性并执行完整 SHA-256 校验，确认后才能补记 `COMMITTED`。不得仅因文件名存在就判定成功。

### 9.6 重连与指数退避

自动重连间隔为：1、2、4、8、16、30、60、60 秒，并加入正负 20％随机抖动，防止 NAS 恢复时集中重试。

- 每次重试都显示倒计时、错误类别和当前次数。
- 身份认证失败、账号锁定、明确权限不足和路径不存在不做盲目自动重试，立即要求用户处理。
- 连接重置、超时、名称解析暂时失败和网络不可达属于可重试错误。
- 8 次快速重试仍失败时，任务进入 `WAITING_FOR_NETWORK`，默认每 60 秒执行轻量连接探测。
- 网络恢复后自动继续；用户也可以手动“立即重试”或暂停。
- 等待状态没有固定失败时限，除非用户取消任务。

### 9.7 最终完整性校验

文件写入完成后：

1. 刷新并关闭远端写句柄。
2. 重新打开本地源文件和远端临时文件。
3. 对本地源文件执行完整 SHA-256；若本次传输从零开始且源文件在传输前后属性未变化，可复用传输过程中连续计算的源摘要。
4. 对 NAS 上的临时文件从头完整回读并计算 SHA-256。
5. 对比摘要与精确字节长度。
6. 再次检查源文件设备号、inode、大小和修改时间。

应用重启后的恢复任务不持久化或恢复 `hashlib` 的内部状态，而是重新读取完整源文件计算最终 SHA-256，以避免依赖不可移植的哈希上下文序列化。

校验失败时保留源文件。远端临时文件保留并标记为校验失败，用户可以重新校验、重新复制或显式清理。应用不得把失败临时文件重命名为最终文件。

### 9.8 原子提交

完整校验成功后：

1. 再次确认最终目标名称未被其他客户端占用。
2. 如果发生竞态冲突，按自动重命名规则分配新的名称并立即持久化。
3. 关闭临时文件的所有句柄。
4. 在同一目标目录执行临时名到最终名的 SMB 重命名。
5. 重新查询最终文件，确认名称、大小和文件标识符合预期。
6. 持久化 `COMMITTED` 状态和最终路径。

若服务端不支持可靠的同目录重命名，MVP 不采用“客户端再复制一遍临时文件到最终文件”的降级方式，因为这会重新引入半成品可见窗口。预检会拒绝该目标目录。

### 9.9 安全删除源文件

移动任务的删除授权必须同时满足：

- 完整 SHA-256 校验成功。
- 最终目标提交成功并可重新查询。
- 源文件自最终哈希读取开始未发生变化。
- 当前删除授权属于当前恢复代次和当前有效 SMB 会话。
- 数据库已持久化最终路径、摘要和提交状态。

如果应用在提交后重启、NAS 会话更换或删除授权状态不明确，必须重新读取目标并完成完整校验，才能重新获得删除授权。

删除文件后再次确认源路径不存在。目录仅在全部子项均达到安全终态后自底向上删除空目录；绝不对来源根目录执行不检查内容的递归删除。

删除失败时：

- 已复制并校验的 NAS 目标保留。
- 本地源文件保留。
- 文件项进入 `SOURCE_RETAINED`。
- 任务进入 `COMPLETED_WITH_WARNINGS`。
- 用户可以在结果页单独重试删除；重试前再次验证目标完整性和源文件未变化。

## 10．冲突与路径规则

### 10.1 自动重命名

默认规则保持扩展名并在基础名后追加序号：

- `movie.mov`
- `movie (1).mov`
- `movie (2).mov`

目录使用相同规则。规划阶段确定名称并持久化；任务恢复不得重复生成新名称。提交瞬间若被其他客户端抢占，分配下一个可用序号并记录一次冲突事件。

### 10.2 覆盖策略

覆盖不是默认策略。用户显式选择覆盖时，原目标先在 NAS 回收站能力允许的情况下移动到隔离名称，再提交新文件；若无法提供可恢复隔离，MVP 拒绝覆盖并建议使用自动重命名。

移动任务采用覆盖时仍必须先完整校验临时文件，不得因用户选择覆盖而降低源文件删除门槛。

### 10.3 Unicode 与大小写

- 内部使用 Python Unicode 字符串。
- 同时保存原始名称和发送到 SMB 的规范化名称。
- 预检按 Unicode NFC 归一化和目标共享的大小写敏感规则检测潜在冲突。
- 对 APFS 常见分解形式与 NAS 组合形式导致的视觉同名进行显式提示。
- 不静默替换非法字符；自动重命名只处理冲突，不掩盖无法表示的名称。

### 10.4 路径安全

- 远端路径始终是共享目录内相对路径。
- 拒绝空组件、`.`、`..`、控制字符和无法由目标 SMB 处理的名称。
- 在预检阶段检测组件长度和完整路径长度。
- 日志默认不记录完整本地路径和完整远端路径。

## 11．边界行为

### 11.1 权限

预检区分列目录、创建文件、写入、读取、刷新、截断、重命名和删除权限。仅能写不能读的目标不能执行完整校验，因此拒绝任务。

文件时间戳和基本只读属性尽力保留。POSIX 所有者、ACL 和扩展属性如果无法可靠映射，记录警告但不影响文件内容成功状态。MVP 不因元数据无法等价映射而删除任何尚未通过内容校验的源文件。

### 11.2 符号链接与别名

MVP 默认跳过符号链接并在结果中说明原因，绝不递归跟随，以避免目录循环、逃逸所选根目录或复制用户未选择的数据。macOS Finder Alias 作为普通文件复制，不解析其目标。

### 11.3 空目录

空目录按源层级创建。移动任务只有在目录内全部文件成功迁移且目录当前仍为空时才删除本地空目录。

### 11.4 磁盘空间不足

预检通过 SMB 查询目标可用空间，并保留 `max(1 GiB, 预计传输量的 5％)` 安全余量。服务端空间报告可能因配额、快照或并发写入而变化，因此传输过程仍要识别空间不足错误。

空间不足时暂停当前任务，不删除源文件，不清理可恢复临时文件。用户释放空间后可以重新预检并继续。

### 11.5 源文件变化

每个文件在规划、打开、复制结束、校验结束和删除前检查指纹。源文件发生变化时：

- 当前远端临时文件不得提交。
- 移动任务不得删除源文件。
- 默认将该文件标记失败，允许用户重新规划该文件。

### 11.6 稀疏文件与特殊文件

MVP 按逻辑字节复制普通稀疏文件，因此目标占用空间可能增加；预检按逻辑大小保守估算。设备文件、FIFO、Socket 和其他非普通文件直接跳过并报告。

### 11.7 NAS 重启与网络切换

NAS 重启、IP 变化、Wi-Fi 切换和 Mac 唤醒均视为会话失效事件。即使旧 TCP 连接表面仍存在，也不复用旧句柄；必须重新连接、重新核验远端临时文件和删除授权。

### 11.8 应用退出与崩溃

正常退出先停止接收新任务，刷新当前检查点并将任务置为 `PAUSED`。强制结束无法执行清理，因此所有恢复正确性必须仅依赖已经提交的 SQLite 状态和远端可观察状态，不能依赖退出回调。

## 12．完整性校验方案与性能权衡

### 12.1 默认模式

默认“完整校验”执行一次完整 NAS 回读。对于 N 字节文件，网络通常需要约 N 字节上传和 N 字节回读，理论网络流量接近 2N，因此校验阶段可能使总耗时接近翻倍。界面在用户加入队列前明确展示这一成本。

用户已经确认接受该成本。稳定性优先，不通过操作系统页缓存命中或仅比较大小来宣称完整。

### 12.2 快速模式

快速模式仅适用于复制任务，包括：

- 精确文件大小比较。
- 头部、尾部和基于任务 UUID 确定性选择的若干中间窗口回读。
- 源文件前后指纹检查。

快速模式必须标注“不能证明整个文件逐字节一致”，其结果不得为源文件删除提供授权。

### 12.3 校验失败处理

- 自动重新读取一次，排除瞬时读取错误。
- 第二次仍不一致则标记 `VERIFY_FAILED`。
- 保存源摘要、目标摘要、大小和失败时间。
- 保留源文件与临时文件。
- 用户可以选择重新校验或从零重新复制。
- 不对失败文件执行自动覆盖最终目标。

## 13．恢复流程

### 13.1 应用启动恢复

启动后：

1. 获取单实例锁并打开 SQLite。
2. 检查数据库完整性和 schema 版本。
3. 将遗留的运行中状态统一标记为 `INTERRUPTED`，不直接标记失败。
4. 枚举未完成任务并展示恢复摘要。
5. 从 Keychain 获取所需凭据；缺失时请求用户重新输入。
6. 按队列顺序逐个恢复，不并发连接多个任务。
7. 对每个文件执行本地来源、远端临时文件和最终文件三方核验。

默认自动恢复排队任务，但涉及身份认证失败、来源变化、最终文件竞态或删除授权重建时暂停并提示用户。

### 13.2 三方状态协调

| 本地源 | 远端临时文件 | 远端最终文件 | 处理 |
|---|---|---|---|
| 存在且未变 | 存在 | 不存在 | 核验断点后续传 |
| 存在且已变 | 存在 | 不存在 | 停止续传，保留两端数据 |
| 存在 | 不存在 | 存在 | 完整校验最终文件后决定完成或重传 |
| 不存在 | 不存在 | 存在 | 完整校验与已存摘要一致后标记完成 |
| 不存在 | 存在 | 不存在 | 不自动继续或删除，要求用户确认来源去向 |
| 存在 | 存在 | 存在 | 视为异常竞态，三者均保留并暂停 |

### 13.3 避免重复删除

源删除动作使用持久化幂等状态：

- 源已不存在且目标已验证时，视为删除已完成。
- 源仍存在时必须重新检查删除授权。
- 删除授权包含源指纹、目标摘要、最终路径和恢复代次。
- 任何字段不一致都撤销授权。

这样可以覆盖“源已删除但数据库来不及更新”以及“数据库记录准备删除但应用尚未删除”两种崩溃窗口。

## 14．安全设计

### 14.1 凭据处理

- 密码只从密码输入框进入内存或写入 macOS Keychain。
- SQLite、普通配置、任务导出和日志中不保存密码。
- 调用 SMB 库时只在建立会话的最短作用域获取密码引用。
- 切换连接配置或退出登录后释放引用。
- Keychain 读取失败时不尝试猜测或使用旧明文缓存。

### 14.2 日志脱敏

日志禁止包含：

- 密码、NTLM 响应、Kerberos 票据、会话密钥。
- 带凭据的 URL。
- 第三方库异常对象中可能包含的认证参数。
- 默认情况下的完整用户名和完整本地路径。

日志使用连接 UUID、任务 UUID、文件项 UUID、错误类别和系统错误码。UI 可以显示用户当前选择的路径；导出诊断报告时默认仅保留文件名和路径哈希，用户可以显式选择包含完整路径。

### 14.3 连接安全限制

- 永久禁用 SMB1。
- 默认要求 SMB3 加密和安全协商。
- 在受信任局域网中，用户可以显式允许仅签名、不加密的 SMB2／SMB3；连接页持续显示风险提示。
- 不提供忽略安全协商失败的开关。
- 检测到公网地址时显示高风险警告，不指导用户把 445 端口直接暴露到互联网。
- 建议远程场景先使用受信任 VPN，再通过内网 SMB 地址连接。

### 14.4 本地数据保护

- 应用数据库和日志目录仅当前用户可访问。
- 导出的报告不自动上传。
- 应用不包含遥测、云端账号或远程控制功能。
- 应用包发布时执行 Developer ID 签名和 Apple 公证。

## 15．错误处理与用户提示规范

### 15.1 错误分类

| 类别 | 示例 | 默认动作 |
|---|---|---|
| `NETWORK` | 超时、连接重置、网络不可达 | 指数退避并重连 |
| `AUTH` | 密码错误、账号锁定 | 停止自动重试，请求用户处理 |
| `PERMISSION` | 不能读、写、重命名或删除 | 停止相关项并说明所需权限 |
| `SPACE` | NAS 空间或配额不足 | 暂停，保留断点 |
| `SOURCE_CHANGED` | 大小、mtime、inode 或摘要变化 | 停止该项，保留源文件 |
| `CONFLICT` | 最终名称被占用 | 自动重命名并记录 |
| `INTEGRITY` | SHA-256 不一致 | 重读一次后失败，禁止提交和删除 |
| `UNSUPPORTED` | 不能截断或可靠重命名 | 预检拒绝任务 |
| `INTERNAL` | 数据库损坏或未分类异常 | 安全停止，保留两端数据 |

### 15.2 用户提示结构

每条错误包含：

1. 发生了什么。
2. 当前数据是否安全。
3. 应用正在做什么。
4. 用户可以采取什么操作。
5. 可展开的技术错误码。

示例：

> 与 NAS 的连接已中断。源文件和远端临时文件均已保留，最近确认的安全断点为 12.5 GiB。应用将在 16 秒后进行第 5 次重连，你也可以立即重试或暂停任务。

禁止只显示“未知错误”“操作失败”或裸异常堆栈。

## 16．任务队列与并发策略

- 队列可以保存多个任务。
- 同一时间只有一个活动任务和一个活动 SMB 文件写流。
- 等待任务可以重新排序或取消。
- 当前任务不能被后续任务抢占；“移到队首”只影响等待任务。
- 暂停当前任务后可以选择继续当前任务或启动下一任务。
- 文件扫描与数据库写入可以批量进行，但不能与另一个任务的文件内容传输并行。

选择串行执行的原因是：更易推断恢复状态、避免多个任务争抢 NAS 磁盘和网络、让速度与剩余时间更可信，并降低 SMB 会话异常时的影响范围。

## 17．测试策略

### 17.1 单元测试

覆盖：

- IP、主机名、IPv6 和 `smb://` 地址解析。
- 远端路径规范化和共享根目录逃逸防护。
- Unicode NFC／NFD 和大小写冲突检测。
- 自动重命名及提交时竞态冲突。
- 任务与文件状态机的全部允许和禁止迁移。
- 指数退避、随机抖动和错误分类。
- 检查点选择、远端长度回退和确认窗口匹配。
- 完整校验、快速校验和校验失败分支。
- 删除授权的生成、撤销、过期和幂等恢复。
- 日志脱敏，确保密码和认证参数不进入日志。
- SQLite 崩溃窗口和事务回滚。

状态机和删除策略采用表驱动测试。任何能从未验证状态到达源删除的路径都必须测试为拒绝。

### 17.2 集成测试

建立可重复的 Samba 测试环境，用于验证：

- SMB2／SMB3 协商、签名和加密。
- 创建、偏移写、刷新、截断、重命名和删除。
- 权限矩阵和空间不足。
- Unicode、长路径、同名与大小写冲突。
- 大文件断点恢复。
- 大量小文件扫描和串行复制。

使用 TCP 故障代理注入延迟、丢连接、半开连接和连接重置。集成测试不能替代真实群晖验证。

### 17.3 真实群晖测试矩阵

至少覆盖：

- 一个当前受支持的 DSM 版本。
- SMB3 加密开启和关闭。
- 普通共享目录和带用户配额的共享目录。
- 有权限、只读、可写不可删和配额不足账号。
- IPv4、主机名、`.local` 名称和 `smb://` 输入。
- 有线网络和 Wi-Fi。

测试前记录群晖型号、DSM 版本、文件系统、SMB 最低／最高协议、加密设置、共享目录设置和用户权限。

### 17.4 人工验证场景

- 新建、编辑、删除连接配置，验证 Keychain 中密码行为。
- 选择多个文件和目录，确认目标层级保留。
- 浏览 NAS 目录和手工填写目标路径。
- 自动重命名文件与目录冲突。
- 暂停、恢复、退出应用和重新打开。
- 查看进度、速度、剩余时间、重试倒计时和最终报告。
- 校验失败时确认源文件仍存在。
- 目标成功但源删除失败时确认目标保留且状态为警告。
- 清理孤立临时文件时确认只能删除精确 UUID 对应文件。

### 17.5 故障注入测试

每种场景同时检查数据库状态、远端临时文件、最终文件和源文件：

1. 写入任意 4 MiB 块过程中关闭 Wi-Fi。
2. `flush` 前、`flush` 后、SQLite 提交前和提交后结束应用。
3. 完整校验进行到 50％时断网。
4. 临时文件重命名前和重命名后结束应用。
5. 删除源文件前和删除后结束应用。
6. 传输过程中重启 NAS。
7. Mac 睡眠后切换到不同网络再唤醒。
8. 传输过程中耗尽 NAS 空间。
9. 传输过程中撤销 NAS 用户权限。
10. 外部客户端抢占最终目标名称或修改目标文件。

故障测试的核心断言是：没有半成品获得最终名称，没有未验证目标触发源删除，恢复后不会重复删除或错误续传。

## 19．主要风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 群晖对刷新、截断或重命名语义存在差异 | 断点或提交不可靠 | 目标目录实际能力探测；不满足则拒绝任务 |
| SMB 会话中断时服务端实际长度与本地记录不一致 | 错误续传或内容错位 | 三方核验、确认窗口哈希、向前回退和截断 |
| 完整回读校验使耗时接近翻倍 | 用户认为任务卡顿 | 分阶段进度、准确说明网络成本；移动仍强制完整校验 |
| Python 打包后的 Keychain 身份变化 | 无法读取已保存密码 | 固定应用标识、签名、公证和升级回归测试 |
| SQLite 损坏或断电 | 无法恢复队列 | 关键事务使用 FULL 同步、启动完整性检查和数据库备份策略 |
| 源文件在传输时被应用外修改 | 校验失败或误删 | 多阶段指纹检查、最终双端哈希、删除授权绑定源指纹 |
| 外部客户端修改目标目录 | 名称竞态或已校验目标变化 | 提交前再次检查；恢复删除授权前重新校验 |
| 大量小文件导致扫描慢或内存高 | UI 卡顿、无法创建任务 | 流式扫描、批量入库、扫描进度和可取消操作 |

## 20．回滚与数据保护策略

### 20.1 任务级回滚

- 在最终提交前，远端内容只存在于 UUID 临时文件。
- 用户取消或应用失败时默认保留可恢复断点，不删除源文件。
- 最终提交后不自动删除目标；源删除失败也保留目标。
- 覆盖模式无法安全隔离旧目标时拒绝执行。

### 20.2 应用版本回滚

- 数据库 schema 迁移前创建本地备份。
- 新版本写入 schema 后，旧版本如果不认识该版本必须拒绝打开，不能尝试降级写入。
- 用户回滚应用版本前可以导出脱敏任务报告；远端 `.part` 文件保持可识别，不会被旧版本自动删除。

### 20.3 紧急停止

发生无法分类的内部错误时，执行器停止继续写入，尽力刷新当前安全边界，关闭会话并保留所有源文件和临时文件。安全停止优先于自动猜测恢复。

## 21．分阶段实施任务与验收标准

以下清单用于设计获批后的实施计划输入；本阶段不创建代码、配置或脚手架。

### 阶段 0：真实 NAS 协议验证

任务：

- 验证群晖目标目录的偏移写、短写、刷新、关闭重开、截断和同目录重命名。
- 验证 NAS 重启和网络中断后的实际文件长度。
- 验证 SMB3 加密、签名和认证错误映射。

验收：

- 输出可重复的能力验证记录。
- 确认 4 MiB 块和 64 MiB 检查点在目标 NAS 上可工作。
- 任一核心能力不足时回到设计评审，不进入安全移动实现。

### 阶段 1：领域状态机与持久化

任务：

- 建立任务、文件项、检查点、尝试和事件模型。
- 实现显式状态迁移和删除安全策略。
- 建立 SQLite 事务与单实例约束。

验收：

- 状态机单元测试覆盖所有允许和禁止路径。
- 无法从未校验状态到达源删除。
- 模拟每个数据库提交窗口后均能确定恢复动作。

### 阶段 2：连接与目标浏览

任务：

- 实现地址解析、连接配置、Keychain 和只读连接测试。
- 实现共享与目录浏览。
- 实现目标目录写能力探测。

验收：

- IP、主机名和 `smb://` 均可连接。
- 密码不出现在数据库、日志和导出报告中。
- 不满足可靠协议的目标目录被明确拒绝。

### 阶段 3：任务规划与边界处理

任务：

- 实现流式源扫描、层级映射、路径校验、空间估算和自动重命名。
- 实现普通文件、目录、符号链接和特殊文件分类。

验收：

- 多来源层级符合已确认规则。
- Unicode、大小写和同名冲突结果稳定可复现。
- 100,000 个小文件扫描不阻塞 UI，内存维持受控。

### 阶段 4：可靠复制引擎

任务：

- 实现临时文件、4 MiB 分块写、短写处理、64 MiB 刷新检查点。
- 实现串行执行、暂停和正常退出。

验收：

- 单个 50 GB 文件可完整复制。
- 暂停和退出后可以从已核验断点继续。
- 半成品始终使用 `.part` 名称。

### 阶段 5：重连与崩溃恢复

任务：

- 实现错误分类、指数退避、等待网络和三方状态协调。
- 实现断点确认窗口回读、回退和截断。

验收：

- 通过断网 10 次、杀进程 20 次、NAS 重启和网络切换测试。
- 恢复后最终 SHA-256 一致。
- 不出现错误偏移续写或重复最终文件。

### 阶段 6：完整校验与安全移动

任务：

- 实现源端和 NAS 端完整 SHA-256。
- 实现同目录提交、删除授权和源删除幂等恢复。

验收：

- 校验失败、源变化和会话变化均阻止源删除。
- 删除失败时目标保留，任务以警告结束。
- 提交和删除的每个崩溃窗口均通过故障注入。

### 阶段 7：UI、报告与可观测性

任务：

- 完成连接、来源、目标、队列、进度和结果页面。
- 完成可操作错误提示和脱敏报告。

验收：

- 用户无需查看终端即可完成任务和恢复。
- 复制、校验、重连和删除状态不会混淆。
- 每个失败项都有原因、数据安全状态和下一步操作。

### 阶段 8：发布验证

任务：

- 执行完整单元、集成、真实群晖和人工测试矩阵。
- 生成签名、公证的 macOS 应用。
- 验证升级、Keychain 访问和数据库迁移。

验收：

- 全部稳定性验收指标通过。
- 发布包在 Apple Silicon 和 Intel Mac 上可启动。
- 安装、升级、降级拒绝和卸载均不误删用户源文件或 NAS 临时文件。

## 22．设计不变量汇总

以下规则在实现评审和测试中具有最高优先级：

1. 未完整校验，不删除源文件。
2. 未成功提交最终名称，不删除源文件。
3. 源文件发生变化，不删除源文件。
4. SMB 会话或应用恢复后，旧删除授权失效。
5. 数据库断点和远端长度不一致时，选择经过内容核验的较早安全边界。
6. 半成品只使用唯一临时名称。
7. 同名目标默认自动重命名，不静默覆盖。
8. 不能证明目标目录支持可靠提交时，拒绝任务。
9. 未分类异常触发安全停止，不触发猜测性删除或提交。
10. 稳定性与数据安全优先于吞吐量和界面上的“快速完成”。
